# Install with a WSO2 Subscription

A WSO2 subscription gives you the WSO2-supported build of WSO2 Agent Manager: the same platform as the community release, with update levels that carry fixes on top of the release. Its Helm charts and images are published to `registry.wso2.com` and signed by WSO2. You install it with the [k3d](./on-k3d.mdx) or [On Your Environment](./on-your-environment.mdx) guide, using the changes on this page.

## Prerequisites

- The registry credentials WSO2 emailed you: a username, which starts with `robot$`, and a token.
- The registry project named in that email:

| Subscription | Registry project |
|---|---|
| Evaluation, from signing up on the WSO2 website | `wso2-agent-manager-evaluations` |
| Paid subscription | `wso2-agent-manager` |

The rest of this page writes the project as `<project>`.

## What Changes From the Community Install

| | Community | WSO2 subscription |
|---|---|---|
| Helm charts | `oci://ghcr.io/wso2/<chart>` | `oci://registry.wso2.com/<project>/helm-charts/<chart>` |
| Agent Manager images | `ghcr.io/wso2/<image>` | `registry.wso2.com/<project>/<image>` |
| Chart version | `1.0.0` | `1.0.0-<update level>` |
| Image tag | `v1.0.0` | `1.0.0.<update level>` |
| Credentials | None | Registry username and token |

The charts in your project already point at the images in the same project, and they reference an image pull secret named `wso2-registry-credentials`. The `helm install` commands in the guides therefore stay the same. Only the Agent Manager images move. The instrumentation image (`amp-python-instrumentation-provider`) and third-party images, such as OpenChoreo, ThunderID, and cert-manager, still come from their public registries.

An update level is a number added to the release. Update level `3` of 1.0.0 is chart version `1.0.0-3` and image tag `1.0.0.3`. Install the newest update level published to your project.

## Install on k3d

### One Command

Run the subscription installer with your project:

```bash
curl -fsSL https://github.com/wso2/agent-manager/releases/download/amp/v1.0.0/k3d-install-subscription.sh | bash -s -- --project <project>
```

The script asks for your registry username and token, and reads the token without echoing it. It then:

1. Checks the same prerequisites as the [community one-command install](./on-k3d.mdx#install).
2. Selects the newest update level published to your project.
3. Downloads the install bundle for that update level from `registry.wso2.com/<project>`, verifies it against its digest, and unpacks it into `~/.wso2-agent-manager/subscription/<project>/1.0.0.<update level>/`.
4. Creates the `amp-local` cluster and installs Agent Manager, pulling every chart and Agent Manager image from your project.

| Option | Description |
|---|---|
| `--project` | `wso2-agent-manager` or `wso2-agent-manager-evaluations`. Without it, the script asks which one. |
| `--update-level` | Install this update level instead of the newest. |
| `--download-only` | Download and verify the bundle, print its location, and stop without installing. It also shows the newest update level published to your project. |

To run the script without prompts, set the credentials first, as described in [Provide the Credentials Without Prompts](#provide-the-credentials-without-prompts).

When the install finishes, it prints the Console URL and the admin sign-in. Continue with [Verify and Access the Platform](./on-k3d.mdx#verify-and-access-the-platform).

## Provide the Credentials Without Prompts

`k3d-install-subscription.sh` reads the credentials from `AMP_REGISTRY_USERNAME` and `AMP_REGISTRY_PASSWORD`, or from a file named by `AMP_REGISTRY_CREDENTIALS_FILE`. Keep them in a file that only you can read rather than on a command line, where they end up in your shell history:

```bash
cat > ~/amp-registry.creds <<'EOF'
AMP_REGISTRY_USERNAME='robot$<project>+<name>'
AMP_REGISTRY_PASSWORD=<token>
EOF
chmod 600 ~/amp-registry.creds
```

Keep the single quotes around the username. Registry usernames contain `$`, which a shell would otherwise expand.

```bash
curl -fsSL https://github.com/wso2/agent-manager/releases/download/amp/v1.0.0/k3d-install-subscription.sh | AMP_REGISTRY_CREDENTIALS_FILE=~/amp-registry.creds bash -s -- --project <project>
```

## Verify the Installation

Check that the Agent Manager pods run images from your project:

```bash
kubectl get pods -n wso2-amp -o jsonpath='{range .items[*]}{.spec.containers[*].image}{"\n"}{end}' | grep amp-
kubectl get pods -n openchoreo-observability-plane -o jsonpath='{range .items[*]}{.spec.containers[*].image}{"\n"}{end}' | grep amp-
```

Each image should start with `registry.wso2.com/<project>/`. The instrumentation image that platform-hosted agents use stays on `ghcr.io/wso2`, which is expected.

## Troubleshooting

### Helm Fails With 401 Unauthorized

Helm is not signed in to `registry.wso2.com`. Run the `helm registry login` command from the **WSO2 Subscription** tab again, and check the username and token in your email.

### Agent Manager Pods Stay in ImagePullBackOff

Check the pod's events with `kubectl describe pod`. The usual causes are:

- The `wso2-registry-credentials` secret is missing from that pod's namespace.
- The secret was created for a registry host other than `registry.wso2.com`.
- The username was not quoted when the secret or credentials file was created, so the shell expanded its `$`.
